# k8si v0.5 — Restore Reporting Design

**Date:** 2026-06-11  
**Status:** Approved  
**Scope:** v0.5.0 only (v0.5.1–0.5.3 are follow-on patch releases)

---

## Context

k8si backs up PVCs via a Kopf operator and restores them via an init container. The init container already does a full restore + sentinel verification on pod startup — but the result disappears into stdout logs. No one knows whether the last restore succeeded, which snapshot was used, or how long it took, unless they go digging in pod logs.

v0.5.0 closes that gap: the init container patches the `K8siBackup` CRD status directly after every restore, using the Kubernetes API. The result is immediately visible in the CRD, the dashboard, and `kubectl get k8sibackup`.

## v0.5.0 — Restore Reporting

### What changes

The init container reports its result to the `K8siBackup` CRD status immediately after the restore completes (or fails). Reporting is **best-effort**: if the PATCH call fails (RBAC missing, API unreachable), a warning is logged but the restore result is unchanged.

### Trigger

Reporting is **opt-in via env vars**. If `K8SI_BACKUP_NAME` is absent, the init container behaves exactly as before — no K8s API calls, no RBAC needed. This preserves backward compatibility for users who run the init container standalone.

### New env vars (init container)

| Env var | Required | Description |
|---------|----------|-------------|
| `K8SI_BACKUP_NAME` | No | Name of the `K8siBackup` CRD to patch |
| `K8SI_BACKUP_NAMESPACE` | No | Namespace of the CRD (defaults to `K8SI_BACKUP_NAME`'s namespace) |

### New CRD status fields

```yaml
status:
  lastRestoreResult: success      # success | failed | skipped
  lastRestoreTime: "2026-06-11T14:30:00Z"
  lastRestoreSnapshotId: abc12345 # restic short ID, empty if skipped
  lastRestoreMessage: "Restored from snapshot abc12345 in 45s"
```

`skipped` means the init container decided no restore was needed (sentinels present, marker file exists, or `NO_RESTORE_FILE` found).

### Data flow

```
Pod starts
  └─ k8si-restore init container
       ├─ existing restore logic (restic restore + sentinel check)
       ├─ [new] _report_to_crd() in try/finally
       │    └─ PATCH k8sibackups/{name}/status
       │         lastRestoreResult: success | failed | skipped
       │         lastRestoreTime:   <now>
       │         lastRestoreSnapshotId: <restic short_id>
       │         lastRestoreMessage: <human summary>
       └─ exit 0 (success) or exit 1 (failure)
  └─ app container starts
```

### Files changed

| File | Change |
|------|--------|
| `k8si/restore.py` | Wrap `run()` body in try/finally; call `_report_to_crd()` always; refactor internal raises to not use `SystemExit` directly until the boundary |
| `k8si/config.py` | Add `backup_name: str \| None` and `backup_namespace: str \| None` (read from `K8SI_BACKUP_NAME`, `K8SI_BACKUP_NAMESPACE`) |
| `deploy/crd.yaml` | Add 4 new status fields under `status.properties` |
| `deploy/rbac.yaml` | Add `k8si-restore` ClusterRole (verb: `patch`, resource: `k8sibackups/status`) and a ClusterRoleBinding to a `k8si-restore` ServiceAccount |
| `k8si/generate.py` | Inject `K8SI_BACKUP_NAME` and `K8SI_BACKUP_NAMESPACE` into the generated init container env block; add `serviceAccountName: k8si-restore` to pod spec |

### RBAC

A new `k8si-restore` ServiceAccount, ClusterRole, and ClusterRoleBinding are added to `deploy/rbac.yaml`:

```yaml
- apiGroups: ["k8si.io"]
  resources: ["k8sibackups/status"]
  verbs: ["patch"]
```

The generated init container YAML uses `serviceAccountName: k8si-restore`. Existing deployments that don't use `k8si generate` are unaffected — they opt in by adding the env vars and service account manually.

### Error handling

- PATCH failure → `log.warning(...)`, continue, restore exit code is unchanged
- `K8SI_BACKUP_NAME` absent → skip reporting silently
- `K8SI_BACKUP_NAMESPACE` absent → default to pod's own namespace (read from `/var/run/secrets/kubernetes.io/serviceaccount/namespace`)

## TDD plan

### Red → Green → Refactor, in this order:

**1. `_report_to_crd()` unit tests** (`tests/test_restore_report.py`, new file)

- `test_report_skipped_when_env_vars_absent` — no K8s call made
- `test_report_patches_correct_fields_on_success` — mock CustomObjectsApi, assert PATCH body
- `test_report_patches_status_subresource` — assert `patch_namespaced_custom_object_status` is called, not the root
- `test_report_failure_is_best_effort` — PATCH raises ApiException, no exception propagates

**2. `restore.run()` integration tests** (`tests/test_restore.py`, extend existing)

- `test_success_reports_to_crd` — full run with mocked backend + mocked K8s, assert report called with `result=success`
- `test_failure_still_reports_to_crd` — backend raises, assert report called with `result=failed` before SystemExit
- `test_skipped_reports_to_crd` — sentinels present path, assert report called with `result=skipped`

**3. Config tests** (`tests/test_config.py`, extend)

- `test_backup_name_read_from_env`
- `test_backup_namespace_defaults_to_pod_namespace`
